# 容量与负载验收

## 1. 容量输入

上线前按区域列出摄像头数、原始 FPS、实际推理步长、分辨率、每帧模型数、平均/峰值事件率、最长中心断网时间、操作台并发数、通知扇出和快照平均大小。不得用演示数据推导生产容量。

关键计算：

- 推理吞吐：`每秒推理帧 = Σ(摄像头 FPS / frame_stride)`，按高危/普通区域分别计算，并用 2 倍高峰作为短时预算。
- edge outbox：`容量需求 = 峰值事件/秒 × 最长断网秒数 × 1.5`，结果必须小于 100,000；否则增加持久容量或缩短恢复目标，禁止丢弃严重事件。
- 中心写入：`事件写 TPS = 边缘事件率 + 断网补传率`。补传限速必须让恢复流量与实时流量并存，不能把 PostgreSQL 或通知 worker 压垮。
- 通知：`delivery TPS = 事件 TPS × 平均命中规则数 × 平均通道数`，网关持续处理能力必须大于峰值且验证 300 秒熔断恢复。
- 数据增长：分别计算事件行、通知 payload、审计、人脸模板、快照和 PostgreSQL/WAL；再加入索引、膨胀和备份 30% 余量。

示例仅说明方法：32 路、每路峰值 0.05 事件/秒、最长断网 8 小时，按 1.5 系数需要 `32 × 0.05 × 28800 × 1.5 = 69120` 条 outbox，低于默认 100,000。现场事件率更高时必须重新计算。

## 2. 操作台读负载

`tests/load/k6-console.js` 模拟大盘一次刷新产生的四个受保护读取。它从每秒 5 次逐步升到 20 次，再以 40 次/秒执行 2 倍高峰阶段，即最高 160 个 HTTP 请求/秒。验收门槛：失败率低于 1%、P95 低于 500 ms、P99 低于 1 s、无 dropped iteration。

每个在线操作台还维持一条 SSE：当前实现不长期占用数据库连接，但默认每秒执行一次信号查询、每 5 秒执行一次账号活动状态/`auth_version` 复核。容量预算至少加入 `SSE 查询/秒 = 在线操作台数 × (1 / poll_seconds + 1 / 5)`，并单独验证 Nginx/API 文件描述符、断线重连风暴、PostgreSQL 短连接获取和 20 秒 REST 降级轮询同时发生的情况。大规模部署可增加数据库通知或 Redis/NATS 唤醒层，但必须保留数据库游标作为可恢复事实来源。

只允许在隔离测试环境使用专用、最小区域、只读 auditor 账号：

```sh
export MINEGUARD_BASE_URL=http://127.0.0.1:8000
export MINEGUARD_LOAD_USERNAME=load-auditor
export MINEGUARD_LOAD_PASSWORD='secret-manager-injected'
k6 run tests/load/k6-console.js
```

该基准在 Compose 宿主机上通过回环 API 执行，隔离 Nginx 的单 IP 防滥用限流；不得把 API 端口改为外网监听。Web 入口另做 429、burst 和多来源限流验收；如一定要从入口测端到端容量，应使用多个批准的负载源并保持生产限流不变。禁止把密码写入命令历史、脚本或结果包。测试后撤销账号会话并停用账号。负载生成器、API、PostgreSQL、worker 和边缘节点时钟必须同步。

## 3. 故障组合

每个容量档位至少执行：稳定 24 小时、API 单副本重启、API 容器重建换 IP、PostgreSQL 60 秒中断、通知网关 15 分钟中断、单路和 25% RTSP 断流、GPU 遥测失败、中心断网后集中补传。记录 CPU、内存、连接数、锁等待、数据库 TPS/WAL、P50/P95/P99、outbox 深度、最老通知年龄和恢复耗时。

故障恢复期间仍须满足：高危检测安全层不放宽、实时事件不被补传饿死、幂等重复为零、法律保留不被清理、浏览器无需人工刷新、worker/edge 无热循环、文件描述符和内存恢复到稳态区间。

## 4. GPU 基准

在目标驱动、TensorRT/Triton、精确模型 SHA-256 和实际矿井视频上分别测 4/16/32 路；报告预处理、排队、推理、跟踪、规则和端到端延迟。每个档位至少预热 10 分钟、稳定采样 60 分钟，输出吞吐、P50/P95/P99、显存峰值、GPU 利用率、功耗、掉帧率和每类召回。

RL 策略只在相同输入轨迹、相同安全约束和至少五个种子下与确定性基线比较。高危召回置信区间下界不能下降；遥测陈旧或 `gpu_healthy=false` 时必须验证确定性回退。

## 5. 证据与结论

结果包固定代码 commit、镜像 digest、模型摘要、配置、数据集版本、k6 输出、Prometheus 快照、数据库统计和异常时间线。任何门槛失败都生成整改工单并重新完整执行对应档位；没有目标硬件和故障演练证据时，不得把容量目标写成已验证能力。
