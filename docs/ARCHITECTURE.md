# 系统架构

## 1. 目标与边界

MineGuard AI 是中心管理面。它负责配置、身份、事件、处置、审计和统计；视频解码与模型推理由边缘工作节点承担，避免原始高清视频全部回传中心。浏览器不能直接播放 RTSP，由媒体网关转换为 WebRTC/HLS；所有 HLS 播放列表和分片先经 Nginx 内部鉴权子请求校验账号区域。

```text
摄像头 / NVR
      |
      v
边缘媒体网关 -----> WebRTC/HLS -----> Vue 操作台
      |
      v
解码 -> 检测 -> 跟踪 -> 人脸/规则 -> 事件去重
      |                                |
      +------ Prometheus 指标          v
                                  消息总线
                                       |
                                       v
Vue 操作台 <---- REST/SSE --------- FastAPI ---- PostgreSQL
                                       |              |
                                       v              v
                                  对象存储         审计/配置
```

当前仓库实现中心 API、Vue 操作台和 MediaMTX/HLS 播放通道；MediaMTX 从数据库登记的只读 RTSP/RTSPS 源按需拉流，边缘工作节点独立分析同一现场源并只向中心补传结构化事件与遥测。真实模型权重、现场 RTSP 源、跨实例消息总线和对象存储属于部署环境资产。无流时界面明确显示连接/重连状态，不用演示图片冒充现场画面。

## 2. 领域划分

- 身份与权限：本地/OIDC 身份、角色、JWT、账号生产区域、人员区域授权和人脸登记状态。
- 视频资源：摄像头、区域、流地址、在线心跳、绑定算法、帧率和延迟。
- 智能事件：事件类型、风险等级、置信度、目标/轨迹元数据、快照引用。
- 处置闭环：`open -> acknowledged -> resolved` 或 `open -> false_positive`，关闭后禁止直接重开。
- 算法治理：模型版本、阈值、配置、启停和部署状态。
- 审计：登录、资源创建、配置变更、事件处置均追加记录。
- 通知投递：规则命中后生成持久 delivery；控制台通道由 worker 本地确认，短信、广播和 Webhook 通过唯一批准的内网通知网关发送并无限指数退避（300 秒封顶）。

## 3. 非功能指标

| 指标 | 生产目标 |
|---|---|
| 中心 API 可用性 | 月度 99.9% |
| 严重事件进入中心 P95 | 不高于 2 秒（边缘推理完成后） |
| 操作台事件查询 P95 | 不高于 500 ms |
| 高危区域检测召回 | 按验收集定义，不低于业务基线且不得因调度策略下降 |
| 审计日志完整性 | 100% 变更操作有操作者、时间、资源和来源 IP |
| RPO / RTO | 当前灾备目标 RPO 不高于 6 小时、RTO 不高于 2 小时；以恢复演练证据为准 |

## 4. 权限基线

| 操作 | admin | operator | auditor |
|---|---:|---:|---:|
| 查看大盘/设备/事件 | 全部 | 授权区域 | 授权区域 |
| 新增或修改摄像头 | 全部 | 授权区域 | 否 |
| 登记人员 | 全部 | 授权区域 | 否 |
| 确认和闭环事件 | 全部 | 授权区域 | 否 |
| 修改算法配置 | 是 | 否 | 否 |
| 查看审计 | 是 | 否 | 是 |

平台已实现企业 OIDC Authorization Code + PKCE、固定 issuer、组允许列表、角色/区域映射和可选受控自动开通；MFA 由企业 IdP 强制。OIDC 与本地登录可并行迁移或关闭本地入口。现场只需把组织组映射到正式区域编码并经过权限审批。

## 5. 扩展与可靠性

- API 无状态化，可水平扩展；JWT 和数据库为共享状态。
- 容器 Web 入口通过 Docker DNS 动态解析 API 与媒体 upstream，10 秒刷新一次，后端容器重建或滚动升级导致 IP 变化时无需人工重启 Nginx。
- Compose 将数据库放入仅 DB/API/worker 可见的内部数据网，Web 只加入控制网和媒体网，MediaMTX 管理 API 默认关闭；入口容器不能直接连接数据库。
- Alembic 与生产引导账号由可重试的一次性 `migrate` 服务执行；PostgreSQL 会话级 advisory lock 跨主机串行化迁移，API 镜像只启动应用进程并等待迁移成功。数据库连接中断会自动释放锁，其他发布 Job 可继续恢复。
- 边缘节点使用独立高熵服务密钥与摄像头白名单，不共享人员账号；心跳驱动节点、GPU、队列和摄像头状态。
- 摄像头心跳、事件写入和视频预览分离，视频故障不阻塞事件查询。
- 事件消费使用至少一次投递，`camera_id + track_id + event_type + time_bucket` 作为幂等键。
- 快照进入 S3 兼容对象存储，数据库只保存 `/snapshots/camera-<id>/YYYY/MM/DD/<uuid>.jpg` 稳定内部引用，不保存会过期或携带签名参数的外部 URL。边缘节点先按绑定摄像头申请短时 PUT，签名同时约束 JPEG、字节数、SHA-256、SSE-S3、法律保留标签和 `If-None-Match: *`，禁止重放覆盖；浏览器在事件区域授权通过后才取得短时 GET 地址。
- 当前提供每 6 小时 custom-format 加密备份、异地原子交接和空库恢复校验；如业务要求收紧到分钟级 RPO，必须再部署持续 WAL 异地归档、复制槽监控和时间点恢复演练。
- OpenTelemetry trace 贯穿边缘事件 ID、消息和 API；Prometheus 采集 RED/USE 指标。
- 当前基线以每个 API worker 最近 2,000 次请求计算 P50/P95，并从数据库统计真实通知队列；多实例生产汇总仍由 Prometheus/OpenTelemetry 完成，界面明确标记当前实例作用域。
- 浏览器对只读 API 采用最多 5 次指数退避；离线时等待系统 `online` 事件，写操作不自动重放以避免重复副作用。
- 事件、处置、设备状态和通知投递在业务事务内写入单调递增的 PostgreSQL 信号序列；各 API 实例通过 SSE 推送，浏览器用 `Last-Event-ID` 续传并无限退避重连。信号不复制敏感业务载荷，只触发受权限保护的 REST 刷新；20 秒轮询保留为降级路径。SSE 握手认证使用立即关闭的一次性数据库会话，不在长流期间占用连接池；流内每 5 秒以短会话重新核对账号活动状态和 `auth_version`，并以 access token 实际剩余寿命限制连接，权限收窄、账号停用或令牌到期会终止流并走统一重新鉴权路径。
- 每路视频由独立 `StreamSupervisor` 管理，断流后使用带抖动的指数退避（1 秒至 30 秒），稳定运行 60 秒后重置退避计数。
- 任一边缘子任务发生不可恢复错误时先广播总停止事件，随后取消仍卡住的协程并清理客户端/GPU 资源，让主进程退出后由容器 `restart: unless-stopped` 拉起；普通 RTSP/中心断网仍在进程内无限恢复，不触发整进程重启。
- 浏览器端实时流与视频流均使用有上限的单次退避、无上限的总重试次数；浏览器网络恢复或任意 API/SSE 请求确认中心恢复后，控制台会重新同步完整授权数据集并续签媒体会话。GET/HEAD 可安全自动重放，写操作不在未知提交结果后盲目重放。
- 生产操作台的摄像头、事件、人员、通知、审计、人脸模板、账号、规则、边缘节点和模型制品均使用服务端分页并隔离迟到响应。`/users`、`/alert-rules`、`/edge-nodes` 和 `/algorithms/artifacts` 的旧数组响应仅用于客户端迁移，最多返回 1000 条；新客户端必须使用对应 `/page` 端点。区域规则和节点使用 500 条主键游标批次完成授权过滤，只保留目标页，避免为跨数据库 JSON 方言牺牲权限语义或形成无界内存列表。
- HLS/native HLS 致命错误还会触发全局去重、15 秒节流的媒体会话续签，覆盖浏览器休眠后媒体 Cookie 过期但普通 API 仍在线的情况；视频组件继续独立退避，多个摄像头不会并发刷新凭据。
- 摄像头 `status/fps/latency/last_seen` 是经认证 edge 心跳聚合出的运行态，管理 PATCH 不能写入或伪造；所有 PATCH 合约拒绝未知字段，配置拼写错误不会以 200 静默忽略。计划维护或退役必须使用后续独立的持久管理意图，不能复用会被遥测覆盖的运行态字段。
- 恢复触发的全量授权数据同步使用单槽串行队列：已有加载进行时只记录一次后续同步意图，当前加载无论成功或失败结束后立即接续，既不丢失恢复信号也不并发放大请求。
- 通知网关断网、超时、401/403/409/429 与 5xx 会持续退避重试并通过幂等键防重复；400/413/415/422 视为必须修正载荷或目标的终态拒绝，不触发网关熔断且不会阻塞后续投递。管理员修正规则或网关契约后手动重试时，系统在行锁内从当前规则刷新目标并保留审计记录。
- 中心 worker 每 30 秒从数据库生成期望媒体路径，通过隔离控制网对账 MediaMTX v3 动态配置；摄像头新增、RTSP 地址轮换和媒体容器重建均无需浏览器或管理员重新配置。源按需拉取，网关控制故障使用独立退避状态，不会拖停通知、生命周期或边缘巡检任务。
- 可管理资源响应携带 `concurrency_token`：一般资源基于规范化 `updated_at`，摄像头和边缘节点则以平台 secret 对配置字段做 HMAC-SHA256，既避免心跳遥测让表单误失效，也不把 RTSP URL 摘要变成弱口令猜测校验器。操作台修改时通过 `If-Match` 回传，服务端取得行锁并完成区域授权后比较；陈旧页面返回 409、全量刷新并提示重新提交。为兼容已有集成客户端，缺少 `If-Match` 的请求暂未强制返回 428。
- 边缘节点使用 `synchronous=FULL` 的 SQLite WAL outbox 保存最多 100,000 条、单条不超过 64 KiB 的待发事件；可选 JPEG 先落入独立持久 spool，再将文件摘要写入 outbox。中心/对象存储断网时继续检测，签名引用先写回 SQLite、对象成功后才提交事件，中心 2xx 且 outbox 删除后才清理本地文件；容量判断和插入由同一写事务原子执行。队列满时进入需人工处置的硬错误，禁止静默丢弃严重事件。
- 边缘节点在启动时同时校验中心基址、节点编号、Triton `host:port`、类别表和摄像头配置，避免把不可恢复的配置错误误判为临时断网；补传键由原始节点/摄像头/事件/轨迹/毫秒时间身份计算 SHA-256，固定为 69 字符。
- 通知 worker 每个实例把心跳、最近成功时间和连续失败次数写入共享数据库；API 依据超时阈值跨进程判断在线状态。worker 的循环边界捕获意外异常并无限指数退避，数据库恢复后自动回写恢复状态。
- 边缘节点上报最近 5 分钟的视频流与中心连接重试计数；控制面结合通知队列最老记录年龄生成低基数运行告警，避免网络抖动长期静默。
- NVML 初始化或采样失败不再表示为 0% 空闲，而是显式上报 `gpu_healthy=false`；中心将节点和对应摄像头降级，并输出大盘与 Prometheus 严重告警。

## 6. 架构决策

- ADR-001：人脸/检测采用可替换 Provider 接口，避免业务层绑定单一模型许可证。
- ADR-002：强化学习仅优化资源调度，并由不可绕过的安全层限制动作。
- ADR-003：实时画面由媒体网关提供，不通过 FastAPI 代理视频字节。
- ADR-004：原始生物特征与业务数据库分库分密钥；Git 和日志禁止出现模板。
- ADR-005：生产数据库使用 Alembic 迁移，`create_all` 仅保留为当前开发引导，迁移基线完成后移除。
- ADR-006：access token 有效期 30 分钟；refresh token 仅以 SHA-256 摘要落库，原值通过 HttpOnly、Secure、SameSite=Strict cookie 传输且每次刷新轮换。
- ADR-007：人脸推理作为独立 Provider，不把 InsightFace 或其他模型的代码/权重许可证传导到中心业务服务；模板用 AES-256-GCM 加密。
- ADR-008：外部通知只通过内网网关，平台数据库不保存短信厂商或广播系统密钥。
- ADR-009：生产模型按 `algorithm_type + model_version + SHA-256` 建立不可变身份，登记者与审批者分离；边缘本地文件、Triton 配置和中心批准记录必须三方一致。
- ADR-010：企业登录采用 OIDC Code + PKCE，外部身份只按固定 issuer/provider 和不可变 `sub` 绑定；令牌不进入前端回调 URL。
- ADR-011：实时更新以数据库持久信号作为真相源，SSE 仅承担通知和续传；不得依赖单进程内存广播，轮询始终可降级。
- ADR-012：角色决定可执行操作，`permitted_areas` 决定可见数据范围；明细、聚合、人员授权和实时信号必须使用同一范围，禁止仅靠前端隐藏。
- ADR-013：视频媒体使用短期 HttpOnly 媒体会话和 Nginx `auth_request`，不使用可分享的长期签名 URL；每个分片均受账号状态、权限版本和摄像头区域约束。
- ADR-014：后台任务可用性以数据库心跳为真相源，容器重启策略只作为进程级兜底；状态页不得把 API 在线等同于异步投递链路在线。
- ADR-015：边缘事件幂等身份由中心按节点 ID 与原始键摘要生成；升级时只接受 `edge_node_id` 一致的旧键，禁止不同服务节点共享全局幂等命名空间。
- ADR-016：生命周期清理仅处理明确终态记录，并以显式法律保留字段覆盖事件、通知、人脸模板和关联审计；设置与解除都要求管理员理由并追加审计。
- ADR-017：数据库备份必须在落盘交接前完成 custom-format 可读性检查、明文摘要、age 加密和密文摘要；恢复工具拒绝非空目标库，RPO/RTO 不经演练不得宣称达标。
- ADR-018：异地备份按“密文、摘要、ready”顺序上传，网络失败无限退避；本地只有在 `.uploaded` 确认后才进入轮换，避免断网期间把唯一备份按时间误删。
- ADR-019：事件快照使用不可变内部对象引用；预签名 URL 永不落库。启用法律保留时先保护对象再提交数据库，解除时先提交数据库再移除对象标签，跨系统失败保持“可能多保留、不得提前删除”并允许同状态重试收敛。
