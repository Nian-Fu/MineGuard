# 强化学习与开源技术调研

> 状态：持续调研文档（第 2 阶段：实现与证据框架；生产选型仍阻断）
> 最近更新：2026-08-22
> 原则：安全规则优先于学习策略；所有外部依赖在生产采用前必须完成许可证、CVE、固定版本和数据合规复核。

## 1. 问题定义

矿井视频平台不应使用强化学习替代人员检测、人脸识别或入侵判定。这些问题由监督学习检测器、特征模型、跟踪器和确定性规则解决。强化学习适合解决动态资源分配：在 GPU 预算、视频路数、事件优先级和时延约束之间选择抽帧率、输入分辨率、批大小和任务队列顺序。

### 1.1 状态、动作与奖励

- 状态 `s_t`：各 GPU 利用率/显存、推理队列深度、各流 FPS/丢帧率、区域风险级别、最近事件率、端到端 P95 时延、遥测年龄、健康 GPU 比例和上一调度动作。上一动作必须进入观测，否则带切换惩罚的过程不满足 Markov 假设。
- 动作 `a_t`：高危流与普通流分别选择帧步长 `{1,2,3,5}` 和检测分辨率 `{640,768,960}`，另选择共享批大小。两类流不能只用一个全局动作，否则保护高危流时会无差别增加全部计算负载。
- 奖励：`R = w1*整体召回代理 + w2*高危召回代理 - w3*P95时延 - w4*积压 - w5*GPU成本 - w6*切换抖动`。
- 硬约束：存在高危流时，其帧步长不超过 2、分辨率不低于 768；动作索引先裁剪到合法空间；遥测超过 30 秒或 GPU 降级时回落到确定性保守配置；安全规则不可被策略关闭；未经批准的动作不可写入生产。

当前中心决策 API 只支持单一全局动作，为保证安全会在任何高危流存在时把全局动作限制到高危边界。这不是双动作策略的生产下发接口。影子模式前必须先交付版本化分流动作、风险组快照、动作 TTL、边缘原子回滚和全链路审计，否则只能离线评估，不能把 PPO 建议写入边缘节点。

召回率不能在线直接获得，因此训练阶段使用带标注回放的漏检率，线上仅使用经校准的代理指标。若把告警数量直接作为正奖励，策略可能通过降低阈值制造告警，这是必须避免的奖励投机。

### 1.2 候选方法比较

| 方法 | 优点 | 风险/局限 | 建议 |
|---|---|---|---|
| 确定性启发式 | 可解释、可审计、冷启动可靠 | 多资源耦合下不一定最优 | 当前生产默认与 RL 安全兜底 |
| Contextual Bandit | 样本效率高，动作影响短时状态时简单 | 不能建模长期队列效应 | 可作为第一版学习基线 |
| PPO | 连续/离散动作兼容，工程资料多 | 样本效率一般，奖励设计敏感 | 离线仿真首选候选 |
| SAC | 连续控制样本效率较高 | 离散组合动作处理更复杂 | 适合副本/批量连续控制实验 |
| DQN 系列 | 离散动作直观 | 组合动作空间迅速膨胀 | 仅用于缩小后的动作空间 |
| Offline RL（CQL/IQL） | 不需在线探索 | 数据覆盖不足会产生外推误差 | 有半年以上可靠日志后评估 |

### 1.3 分阶段上线门槛

1. 仿真：历史视频回放与合成负载，和固定策略比较至少 7 天等价负载。
2. 离线评估：关键区域召回按同一候选在五条工作负载 trace 上的配对差值计算 Student-t 95% 置信区间，下界不得低于零；该区间只刻画回放差异，至少五次独立训练的模型间方差必须另报。P95 时延改善目标不少于 15%，动作切换次数受控。评估报告必须绑定冻结 trace 和候选模型 SHA-256，并核对故障窗口安全覆盖次数；锁定候选前只能查看独立开发 trace，禁止把正式准入种子用于反复调参。
3. 影子模式：策略只输出建议，不控制生产；记录建议与实际结果至少 14 天。
4. 金丝雀：仅普通区域 5% 流量，自动回滚条件包括延迟、漏检代理、GPU OOM 或节点抖动。
5. 扩容：每阶段由安全、生产、算法三方签字；高危区域最后接入。

## 2. 强化学习框架调研

| 项目 | GitHub | 许可证 | 适用性判断 |
|---|---|---|---|
| Stable-Baselines3 | `DLR-RM/stable-baselines3` | MIT | PPO/SAC/DQN 基线成熟，适合单机训练和可重复实验；本项目首选原型框架 |
| Ray RLlib | `ray-project/ray` | Apache-2.0 | 分布式采样和大规模训练强，但运维复杂；流量规模扩大后再引入 |
| CleanRL | `vwxyzjn/cleanrl` | MIT | 单文件实现便于算法审计与研究复现，不直接作为服务运行时 |
| Tianshou | `thu-ml/tianshou` | MIT | Collector/Buffer 设计灵活，中文生态友好；作为 SB3 的对照候选 |
| d3rlpy | `takuseno/d3rlpy` | MIT | Offline RL 算法覆盖较好；日志积累后用于 CQL/IQL 实验 |
| Gymnasium | `Farama-Foundation/Gymnasium` | MIT | 自定义资源调度环境的标准接口 |

选型结论：`Gymnasium + Stable-Baselines3 PPO` 构建首个数字孪生环境；`CleanRL` 用于核对 PPO 实现；生产推理服务只加载导出的策略并经过安全层，不携带训练依赖。尚未完成固定 commit 的供应链复核前，不把任何项目直接锁定为生产依赖。

## 4. 人脸识别专项结论

- 链路：人脸检测 -> 五点对齐 -> 质量门禁 -> 活体/攻击检测 -> 特征向量 -> 加密特征库近邻检索 -> 阈值校准 -> 身份/陌生人结果。
- 只保存有合法授权人员的模板；原图设置最短留存期；向量视为敏感生物识别信息并使用独立密钥加密。
- 阈值不可照搬公开数据集。应使用井下照度、粉尘、头灯、口罩、安全帽遮挡数据绘制 ROC/DET，在 FAR 上限约束下确定阈值。
- 1:N 陌生人判定必须使用独立阈值；低质量样本返回“无法判断”，不能强行匹配。
- 跨人群、班次、设备和区域报告 FAR/FRR 分层指标；发现显著差异时停止自动联动。
- 人脸事件仅作为辅助研判，涉及纪律处分或人身安全的决策必须由授权人员复核。

## 5. 三天研究清单

已完成但尚无动态运行证据：v3 trace 候选生成器、PPO/启发式/随机评估入口、线性 contextual bandit、去队列/去故障状态消融、模型摘要绑定、严格准入报告校验和五类独立 ADR 骨架。v3 逐种子绑定总步数、高危样本覆盖、故障覆盖和 trace 摘要，并禁止放宽 10% 退化上限。由于当前没有 Python/NumPy，冻结常量尚未在两个隔离环境独立复现，协议明确为 `unsealed` 且准入失败关闭；运行时动态现算摘要不能作为冻结证据。上述代码证明实验协议与阻断路径已经编码，不证明性能或生产可用性。

仍待真实环境完成：

- 对候选仓库记录最新稳定 tag、commit、维护活跃度、公开 CVE、许可证文本哈希。
- 使用目标 GPU 做 4/16/32 路视频吞吐与 P50/P95/P99 延迟基准。
- 制作至少 5000 帧矿井域小样本，比较检测精度、遮挡鲁棒性与夜间表现。
- 完成人脸数据保护影响评估（DPIA）、留存策略和权限矩阵评审。
- 完成 PPO/启发式/随机策略的固定种子实验、置信区间和消融实验；最终模型选择必须另用未参与调参的封存回放集复核，避免反复观察公开五种子造成评估过拟合。
- 将 `docs/adr/ADR-020..024` 的许可证、供应链、现场数据、目标 GPU、故障恢复与回滚证据全部补齐；缺一项都保持 `Proposed / evidence blocked`，不得改为 `Accepted`。
