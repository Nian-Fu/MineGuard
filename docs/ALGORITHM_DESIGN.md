# 算法设计与验收

## 1. 流水线

1. 拉流与时间同步：RTSP 重连、NTP 校时、帧时间戳和摄像头 ID。
2. 质量诊断：黑屏、遮挡、抖动、低照和断流先于业务算法。
3. 人员/安全帽检测：输出框、类别、置信度；按区域独立阈值。
4. ByteTrack 类跟踪：生成稳定 `track_id`，抑制逐帧重复告警。
5. 规则引擎：多边形越界、停留时间、方向、人数、时间窗和人员授权。
6. 人脸分支：对齐、质量、活体、向量检索和未知身份判定。
7. 事件融合：时间窗去重、风险升级、快照脱敏和消息发布。

框架无关的业务规则位于 `backend/app/vision/rules.py`：以人员脚点做多边形判定，支持停留时间、单轨迹单次入侵告警、带方向越线计数和区域唯一轨迹聚集计数。节点启动时拒绝重复点、零面积、非有限或自交多边形，规则持续时间拒绝布尔和非有限值，避免错误标定静默漏报。模型适配器只需输出统一 `Track`，无需在每个模型实现里重复业务规则。

## 2. 事件规则

### 入侵

目标中心点或脚点进入多边形，并连续保持 `dwell_seconds` 才触发。高危禁区默认 2 秒，一般区域默认 5 秒；轨迹离开区域后设冷却窗口。使用透视校正后的脚点可减少近大远小造成的边界误判。

### 人头/聚集

“人头技术”在本系统解释为人员计数与聚集检测，不做无法律依据的身份推断。优先使用 person 检测加轨迹去重；严重遮挡区域可增加 head 检测分支。计数按穿线方向或区域内唯一轨迹计算，不累计视频帧中的重复目标。

边缘节点把每个区域当前唯一轨迹数放入心跳 `area_counts`；每个 edge 配置要求同一区域恰好一台摄像头设置 `counting_authority=true`，其他重叠视野必须显式设为 `false`。中心只使用在线节点；若跨节点仍对同一区域重复上报，中心禁止相加，暂取单节点最大值并产生 `area_counter_conflict` 高风险告警。该值只用于避免明显重复的降级展示，必须修正现场全局权威映射后才可作为精确人数。

### 安全帽

检测 person/head/helmet 并建立空间归属。head→person 与 helmet→head/person 采用确定性最近中心一对一分配，同一检测框不得让多个重叠人员同时合规；已分配头部的人员禁止回退到宽松的上半身 helmet 匹配，降低手持帽误判。连续多帧无安全帽且目标质量足够时才告警。验收按人员实例计算 precision/recall，而非只按框 mAP。

### 人脸

人脸质量分低于阈值返回不可判定；活体失败只产生攻击风险事件，不进入身份检索。1:1 验证和 1:N 检索使用不同阈值并按现场验证集标定。

中心人脸链路位于 `backend/app/services/face.py` 和 `backend/app/api/faces.py`。外部 Provider 接收瞬时图像并返回特征、质量、活体、模型版本与模型制品 SHA-256；中心要求单人脸、质量与活体同时达标后，使用 AES-256-GCM 和绑定 `person_id:model_version:model_sha256` 的附加认证数据加密模板。数据库与 API 均不保存或返回原始登记照片、明文向量或密钥。生产准入开启时，登记、人工识别和 edge 实时识别均要求该版本与摘要对应 `face_recognition` 已审批制品；旧模板因未绑定摘要在 `0011` 升级时保留作审计但自动停用，必须重新登记。

Provider JSON 限制为 256 KiB，embedding 必须是 64-2048 个有限且可表示为 float32 的数值；模板解密前先核对 12 字节 nonce 和对应的有界 AES-GCM 密文长度，解密后再次校验维度与有限值。当前中心使用有界顺序匹配，单次最多处理 5000 个同模型活动模板；超限返回 503 而不做不完整匹配。超过该规模必须经独立 ADR、召回/延迟/租户隔离和供应链验收后接入受审向量索引，不能静默提高无界暴力检索上限。

Provider 契约：

```json
POST /v1/embeddings (multipart field: image)
{
  "embedding": [0.012, -0.034],
  "quality": 0.91,
  "liveness": 0.97,
  "face_count": 1,
  "provider": "approved-provider-id",
  "model_version": "arcface-mine-v1.0.0",
  "model_sha256": "<64 lowercase hex characters>"
}
```

生产启用需配置 `MINEGUARD_FACE_ENABLED=true`、推理服务内网 URL 和 KMS 下发的 32 字节 Base64 模板密钥。模型版本不一致的模板不会混合比对；大规模人员库应把当前中心端线性检索替换为支持加密边界的向量检索服务。

实时视频分支由 edge 对检测模型的 `head` 与人员 track 做一对一空间关联，仅在摄像头显式设置 `face_recognition_enabled=true` 后启用。每路最多一个短时探针请求，按 track 采样并设置事件冷却；裁剪 JPEG 只在内存中通过节点服务身份发送到 `/faces/edge-identify`，不写入 SQLite、对象存储或日志。中心再次检查节点摄像头白名单、质量、活体、模型版本、制品摘要与模板阈值，只返回人员 ID、相似度、模型身份和该摄像头区域授权结论。低质量、多脸或活体失败属于“不可判定”，不得生成 `unknown_face`；识别成功后 edge 只把不含图像/向量的 `face_match` 或 `unknown_face` 事件写入持久 outbox，中心入库时再次确认该人脸制品仍获批准。中心或 Provider 断开时视频检测继续，人脸子链路只增加自己的降级原因并在后续采样自动恢复，不会清除 RTSP、快照或 outbox 的其他故障，也不把历史生物图像落盘补算。

## 3. 模型与数据版本

每个模型发布包必须包含：权重哈希、训练代码 commit、数据集版本、类别映射、预处理、阈值、目标运行时、量化方式、评估报告和审批人。模型仓库使用不可变版本号，禁止覆盖 `latest`。

边缘适配器位于 `backend/app/edge/model_manifest.py` 和 `inference.py`。节点启动先计算本地制品 SHA-256，再核对 Triton 模型配置的 `parameters.artifact_sha256.string_value`；两者必须同时等于中心批准记录。检测输出采用明确的 Nx6 `[x1,y1,x2,y2,score,class]` 契约，跟踪使用 Supervision 的 ByteTrack 实现，不在业务代码中重新手写跟踪算法。

数据分为 train/validation/test/acceptance 四部分，按摄像头和日期分组切分，避免相邻帧泄漏。验收集由生产安全部门封存，算法团队不可用于调参。

## 4. 验收矩阵

| 场景 | 核心指标 | 必测切片 |
|---|---|---|
| 入侵 | 事件 recall、每路每天误报数、触发延迟 | 昼夜、粉尘、雨雪、遮挡、逆光 |
| 人员计数 | MAE/MAPE、跨线方向准确率 | 稠密、交叉、停留、折返 |
| 安全帽 | 人员级 precision/recall | 帽色、头灯、手持帽、部分遮挡 |
| 人脸 | TAR@FAR、未知人误接受率、不可判定率 | 安全帽、口罩、年龄、照度、相机角度 |
| 跟踪 | IDF1、ID switch、轨迹完整率 | 交叉、长遮挡、出入画面 |
| 性能 | 吞吐、P50/P95/P99、显存、功耗 | 4/16/32 路、节点失效、突发告警 |

## 5. RL 调度安全设计

`backend/app/services/rl_scheduler.py` 当前实现确定性安全策略，作为将来策略服务的同一接口。入口严格限制 GPU、队列、流数量与区域比例；遥测超过 30 秒或健康 GPU 比例下降时直接进入确定性保守动作。策略输出必须先经过 Safety Layer：动作范围裁剪、高危区域覆盖、资源上限检查、切换速率限制和故障回退。线上保留 kill switch，可在一分钟内统一退回静态配置。

训练环境使用记录的视频复杂度和实测推理延迟模型，不用真实生产系统在线探索。奖励、随机种子、归一化参数和评估数据版本必须进入实验记录。上线标准采用置信区间而不是单次平均值。

当前研究环境把高危流和普通流的步长/分辨率拆成独立动作，避免用一个全局动作保护高危区时把所有普通流同时切到最高成本。安全层对任何非零高危占比强制执行 `stride <= 2`、`resolution >= 768`；陈旧遥测或任一 GPU 降级使用固定安全动作。评估脚本对五个固定种子的整体召回、高危召回、P95/P99、队列峰值、GPU 平均/P95 负载、动作切换和安全覆盖次数报告均值、样本标准差和 Student-t 95% 置信区间。

当前生产 `/algorithms/scheduler/decision` 仍只返回一套统一 stride/resolution，因此只要存在高危流就对全部流采用高危安全动作。该接口可用于确定性安全基线，但不能承载研究环境的双动作 PPO。进入真实影子模式前必须定义带版本的分流动作契约、摄像头风险分组、边缘原子应用/回滚、动作 TTL 和建议/实际结果审计；完成之前不得把 PPO 输出接到边缘执行。
