# ADR-022：实时媒体网关

- 状态：Proposed / evidence blocked
- 日期：2026-08-22
- 决策范围：RTSP/RTSPS 到浏览器 HLS/WebRTC 的媒体路径

## 背景与决策

拟采用 MediaMTX 作为媒体网关，按需拉取数据库登记的只读源；FastAPI 不代理视频字节。浏览器只访问同源入口，每个播放列表和分片都经 Nginx `auth_request` 校验短期 HttpOnly 媒体会话与摄像头区域权限。MediaMTX 管理 API 只在独立控制网暴露，由中心 worker 周期对账并自动恢复。

候选包括 MediaMTX、GStreamer 自建网关和厂商流媒体服务。当前实现优先选择较小的控制面和多协议支持，但镜像版本、v3 API 与现场编解码兼容性尚无运行证据。

## 后果

- 不暴露匿名 RTSP、HLS 或管理端口；RTSP 凭据只在服务端解密并禁止写入日志。
- HLS、SSE 与 API 各自无限总重试且有单次退避上限，恢复时重新鉴权；管理写入不自动盲重放。
- 必须保留上一已批准镜像 digest、配置和回滚步骤，媒体故障不得阻塞事件查询和处置。

## 转为 Accepted 的证据

1. 固定镜像 digest、源码 commit、许可证哈希、SBOM、签名和 CVE 扫描。
2. 使用现场 RTSP/RTSPS、H.264/H.265 和目标浏览器验证首帧、长播、休眠恢复、分片鉴权、权限撤销与断流恢复。
3. 在 4/16/32 路并发下报告网关 CPU、内存、带宽、P95 首帧和重连时间。
4. 完成管理 API 失联、容器重建、坏源隔离、凭据轮换、越权分片和路径穿越负向演练。
