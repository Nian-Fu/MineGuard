# ADR-020：检测训练与部署框架

- 状态：Proposed / evidence blocked
- 日期：2026-08-22
- 决策范围：人员、人脸前置检测、安全帽和矿井域目标检测

## 背景与决策

拟采用 MMDetection 作为自有矿井域数据的检测训练框架，以 MMDeploy 导出 ONNX/TensorRT 制品；中心业务只依赖版本化 Provider 契约，不直接依赖训练框架。Ultralytics 仅保留为隔离技术对照，在 AGPL 或商业许可未完成书面审批前不得进入默认闭源生产镜像。人脸识别权重与检测代码分别审批，公开 InsightFace 权重不自动获得商用许可。

决策驱动因素是矿井域再训练能力、可审计配置、部署格式、GPU 性能、许可证边界、维护活跃度和退出成本。候选包括 MMDetection/MMDeploy、Ultralytics 和自建 PyTorch 管线；当前静态评分不足以排除实际硬件上的兼容性差异。

## 后果

- 训练依赖不进入 FastAPI 管理面，运行制品以模型类型、版本和 SHA-256 建立不可变身份。
- 数据集按摄像头、班次和日期分组切分，禁止相邻帧跨训练/验收集泄漏。
- 导出前后必须比较召回、误报和数值漂移；TensorRT 引擎必须绑定 GPU 架构与运行时版本。
- 保留 Provider 和 ONNX 边界，若框架停止维护或许可变化可替换训练实现。

## 转为 Accepted 的证据

1. 固定完整 commit、签名 tag、许可证文件 SHA-256、依赖哈希锁、SBOM、CVE 扫描和模型权重授权。
2. 至少 5000 帧矿井域标注集，报告人员/安全帽按照度、粉尘、遮挡、设备和区域分层的 Precision、Recall、mAP 与置信区间。
3. 在目标 GPU 上完成 4/16/32 路的 P50/P95/P99、吞吐、显存、功耗、冷启动和 24 小时稳定性测试。
4. 完成导出一致性、坏模型拒绝、OOM 降级、回滚到上一摘要和数据合规审查。
